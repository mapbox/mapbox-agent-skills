# iOS: Navigation SDK v2 → v3

Mappings from Navigation SDK for iOS v2 (`MapboxCoreNavigation`, `MapboxNavigation`) to v3 (`MapboxNavigationCore`, `MapboxNavigationUIKit`).

**Requirements for v3:** Swift 5.9+, **Xcode 16+**, iOS 14+. Navigation v3 depends on Maps SDK v11. Migrate the map layer with `mapbox-ios-maps-v10-to-v11-migration`.

**Distribution: Swift Package Manager only.** v3 has no podspec and no Carthage build. Package URL `https://github.com/mapbox/mapbox-navigation-ios.git`; products `MapboxNavigationCore` and `MapboxNavigationUIKit` (Maps v11 comes in as a dependency). A CocoaPods or Carthage app must move the navigation and map dependencies to SPM. See [Project setup](#project-setup-cocoapods-or-carthage-to-spm). This also applies to Maps v11 in that app, even though Maps v11 itself still ships a podspec: both SDK generations come through the same package graph.

**Libraries:**

| v2                     | v3                                                | Notes                                                                                               |
| ---------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `MapboxCoreNavigation` | `MapboxNavigationCore`                            | Core is rebuilt around one `MapboxNavigation` object and Combine publishers                         |
| `MapboxNavigation`     | `MapboxNavigationUIKit`                           | Same UI components (`NavigationViewController`, `NavigationView`, `PreviewViewController`, CarPlay) |
| `MapboxDirections`     | `MapboxDirections` (bundled)                      | Route requests go through `RoutingProvider`, not `Directions.shared`                                |
| `NavigationMapView`    | `NavigationMapView` in **`MapboxNavigationCore`** | Moved from the UI library to core                                                                   |

**Version notes:** the v3 API changed during 3.x. Check deprecations on the version you target. For example, `RerouteConfig.optionsCustomization` is deprecated in favor of `urlOptionsCustomization`. Release tags changed format at 3.28 (`v3.27.3` → `3.28.0`): compare versions, not tag strings (SKILL.md rule 7).

**Re-exports:** v3 modules don't re-export `UIKit`, `CoreLocation` or `MapboxDirections`, and `MapboxNavigationUIKit` doesn't re-export `MapboxNavigationCore`: files using both need both imports. Add `import CoreLocation` (for `CLLocationCoordinate2D`, `CLLocationCoordinate2DMake`) and `import MapboxDirections` (for `RouteOptions`, `Waypoint`, `RouteStep`) where they're used. v2 `import MapboxSpeech` goes away: `SpeechOptions` and `SpeechError` are in `MapboxNavigationCore`, and `SpeechOptions(text:)` now requires `locale:`.

**Value types:** in v3 `MapboxDirections`, `Route`, `RouteResponse`, `RouteLeg`, `RouteStep`, `Waypoint` and `Incident` are structs. Code that mutates them through a `let` reference, or relies on reference identity, must change (`var` copies, write back).

## Swift concurrency

v2 was callback- and notification-based with no actor annotations. v3 is `@MainActor` across most of its surface. In production-size apps this is the largest error class after renames, and the one most likely to compile and then **crash at runtime**.

- **`@MainActor` in v3:** `MapboxNavigationProvider.mapboxNavigation` and most provider members; the controllers you get from it (`navigation()`, `tripSession()`, `routingProvider()`, `electronicHorizon()`, `historyRecorder()`, `eventsManager()`); `NavigationLocationManager.init`; `NavigationMapView`, `NavigationCamera` and viewport data sources; `MapboxSpeechSynthesizer` and all UI components. `MapboxNavigationProvider.init(coreConfig:)` itself is **not** isolated.
- **Typical v2 code that breaks:** services and singletons created from a background queue or a startup `Task`; settings and network callbacks that call into navigation; `NavigationLocationManager` subclasses built off the main thread; test specs (Quick/XCTest) that call these APIs from nonisolated contexts.
- **Fixes, in order of preference:** annotate the app type that owns navigation objects `@MainActor`; hop with `Task { @MainActor in … }` or `await MainActor.run { … }` from nonisolated callbacks; mark test helpers `@MainActor`.
- **`MainActor.assumeIsolated` only where the code is already guaranteed to run on the main thread** (UIKit callbacks, `DispatchQueue.main`). It doesn't move work to the main thread. It traps at runtime when called elsewhere, for example from a startup `Task` on the cooperative pool. That crash happens at launch and no build catches it.
- Closures the SDK calls you back on are `@Sendable` and may run **off** the main actor: `CoreConfig.multilegAdvancing`, `fasterRouteApproval`, `MultiplexedSpeechSynthesizer`'s `skuTokenProvider`, custom `SpeechSynthesizing` callbacks. Capture `Sendable` values, not main-actor objects.
- `Style.apply()` isn't main-actor isolated but `StyleManager` calls it on the main thread, so `MainActor.assumeIsolated` is safe there for setting `@MainActor` appearance.

Do this as area 1, before touching code. No skill tool edits `project.pbxproj` for you: use Xcode, or a script with the `xcodeproj` Ruby gem (installed with CocoaPods), rather than hand-editing the file.

1. `pod deintegrate` (or remove by hand): `[CP] Check Pods Manifest.lock`, `[CP] Embed Pods Frameworks` and `[CP] Copy Pods Resources` build phases, `Pods-*.xcconfig` base configurations, `Pods_*.framework` links. 2. Remove **every** leftover `MapboxNavigation.framework`, `MapboxCoreNavigation.framework`, `MapboxMaps.framework` file reference and link entry. A stale one compiles but fails at link time (`framework 'MapboxNavigation' not found`).
3. Add the package `https://github.com/mapbox/mapbox-navigation-ios.git`, "up to next major" from `3.0.0`, and link `MapboxNavigationCore` and `MapboxNavigationUIKit` to each target that uses navigation. Don't add Maps separately unless the app needs a newer v11 than navigation pins.
4. Raise `IPHONEOS_DEPLOYMENT_TARGET` to at least 14.0 in every configuration.
5. Storyboards that reference SDK storyboards or resources by bundle: replace `org.cocoapods.MapboxNavigation` with the SPM resource bundle ID. 6. Update README, CI (`pod install`, `pod update`, cache keys) and the Gemfile if CocoaPods was its only reason.

### Other Mapbox SDKs in the same app

Navigation v3 pins MapboxCommon (24.x for 3.35) and Maps v11. Every other Mapbox SDK in the package graph must accept the same Common version, or SPM won't resolve. Do this in area 1 and log it as a decision: it's a forced upgrade of another SDK, with its own API changes.

- **Search:** Search 1.x requires Common below 24, so it must move to the 2.x release that matches the navigation release's Common. Changes seen in practice: `supportSBS:` → `apiType:`, `reverseGeocoding(options:completion:)` → `reverse(options:completion:)`, `setTileStore(_:accessToken:)` → `setTileStore(_:)`. Check the Search changelog for the rest `[VERIFY WITH MAPBOX]`.
- **App modules that pin `mapbox-common-ios` directly:** raise the pin to match.
- **MapboxCommon 24 API changes** (they affect the app even if it never imported navigation there): HTTP interceptors moved to the continuation-based API (`onDownload` is gone), `UploadServiceFactory` → `HttpServiceFactory.getInstance().upload(for:)`, `EventsServerOptions(token:userAgentFragment:…)` → `EventsServerOptions(sdkInformation:…)`, and `TileStoreOptions.mapboxAccessToken` (per-domain tile tokens) is gone `[VERIFY WITH MAPBOX]`. The interceptor change is also in the Maps skill.
- `MapboxGeocoder` and `MapboxStatic` (Swift web API wrappers) don't depend on Common and usually need no change.

## Provider lifecycle

v3 allows only **one live `MapboxNavigationProvider`** at a time: creating a second while the first is alive hits `preconditionFailure("MapboxNavigationProvider was instantiated twice.")`. v2 apps often created a `MapboxNavigationService` per screen.

- `NavigationOptions()` (the no-argument initializer) builds **its own** `MapboxNavigationProvider`. If the app already has one alive, that hits the precondition. Always build `NavigationOptions(mapboxNavigation:voiceController:eventsManager:…)` from the app's provider, including for storyboard-created view controllers (`prepareViewLoading(navigationRoutes:navigationOptions:)`).
- **One provider per screen** works only if the previous screen's provider is **deallocated** before the next one is created (Mapbox's own v3 examples own the provider in each view controller). The build can't check this; the crash happens at runtime when the screen opens a second time. Before choosing it, find what owns each screen and confirm it is released:
  - child view controllers added with `addChild` but never removed with `removeFromParent()` (a container that only removes the child's view keeps the child and its provider alive)
  - view controllers cached in properties, arrays or a coordinator, or kept by a navigation stack the user returns to
  - strong `self` captures in Combine sinks, `Task`s, timers and SDK closures (`multilegAdvancing`, speech synthesizers)

  If any of these keep a screen alive and fixing them isn't in scope, use one app-wide provider. Check: open the same screen twice in a row, then two different navigation screens one after another.

- **One app-wide provider** works for apps with many navigation screens. Then note which `CoreConfig` fields can change at runtime: `provider.apply(coreConfig:)` re-applies only the location source, TTS config, locale, log level, credentials token and copilot. Other fields (`multilegAdvancing`, `routingConfig` including reroute and faster-route config, `historyRecordingConfig`, `electronicHorizonConfig`, `predictiveCacheConfig`) only take effect when the navigator is created. Per-screen differences in those need a decision.
- `CoreConfig ==` and `TTSConfig ==` compare closures and custom synthesizers by presence, not identity. Don't rely on equality to detect a changed closure.
- Every `provider.apply(coreConfig:)` also **rebuilds the route voice controller's speech synthesizer** from `ttsConfig` (`MapboxNavigationProvider.apply`). Anything the app set on the synthesizer directly (`muted`, `volume`, `managesAudioSession`, a delegate) is lost when it switches the location source. Re-apply those settings after each `apply(coreConfig:)`, or keep them in the app's own `SpeechSynthesizing` passed through `ttsConfig: .custom(...)`.

`NavigationViewController` lifecycle in v3: it calls `tripSession().startActiveGuidance(with:startLegIndex: 0)` itself when its view loads, doesn't configure simulation (set `locationSource` on the provider **before** creating it), and sets the session to idle when dismissed.

Custom location managers (v2: a `NavigationLocationManager` subclass passed to `MapboxNavigationService` or `PassiveLocationManager`). Keep the app's manager and bridge it to the public `LocationClient`:

```swift
@MainActor
final class LocationManagerBridge: NSObject, CLLocationManagerDelegate {
    let manager: NavigationLocationManager   // the app's v2 subclass, unchanged
    private let locationSubject = PassthroughSubject<CLLocation, Never>()
    private let headingSubject = PassthroughSubject<CLHeading, Never>()

    init(manager: NavigationLocationManager) {
        self.manager = manager
        super.init()
        manager.delegate = self   // the bridge owns the delegate; fan out to the app from here if it needs updates
    }

    lazy var locationClient = LocationClient(
        locations: locationSubject.eraseToAnyPublisher(),
        headings: headingSubject.eraseToAnyPublisher(),
        startUpdatingLocation: { [manager] in manager.startUpdatingLocation() },
        stopUpdatingLocation: { [manager] in manager.stopUpdatingLocation() },
        startUpdatingHeading: { [manager] in manager.startUpdatingHeading() },
        stopUpdatingHeading: { [manager] in manager.stopUpdatingHeading() }
    )

    nonisolated func locationManager(_ manager: CLLocationManager, didUpdateLocations locations: [CLLocation]) {
        MainActor.assumeIsolated { locations.forEach(locationSubject.send) }   // CLLocationManager calls back on the main thread
    }

    nonisolated func locationManager(_ manager: CLLocationManager, didUpdateHeading newHeading: CLHeading) {
        MainActor.assumeIsolated { headingSubject.send(newHeading) }
    }
}

// CoreConfig(locationSource: .custom(bridge.locationClient)), or switch at runtime:
var config = provider.coreConfig
config.locationSource = .custom(bridge.locationClient)
provider.apply(coreConfig: config)
```

Create the bridge and its manager on the main actor. Apps that switch between several managers (system, simulated, replay) keep one bridge per manager and switch with `apply(coreConfig:)`. Restore the app's source after a trip that used `.simulation`.

Taps and long presses on a `NavigationMapView`: the SDK already installs its gesture handling and reports to `NavigationMapViewDelegate`. Use it instead of the Maps skill's `TapInteraction` / `LongPressInteraction`, or a v2-style `UILongPressGestureRecognizer`, which add a second recognizer on top of the SDK's.

- `navigationMapView(_:userDidLongTap: MapPoint)`: any long press. Fires when the press **begins** (v2 examples usually acted on `.ended`).
- `navigationMapView(_:didSelect alternativeRoute:)`: a tap near an alternative route line.
- `navigationMapView(_:didSelect waypoint:)`: a tap near an intermediate waypoint.
- `navigationMapView(_:userDidTap: MapPoint)`: only a tap on a **named map feature** (`mapPoint.name != nil`), after the checks above. It is not a "tap anywhere" callback. For taps on empty map, keep a Maps v11 `TapInteraction` and accept that it also fires for route taps.

#### Preview map screen

The most common v2 screen: a map that shows the user, long-press to request a route, tap to pick an alternative, a button that starts `NavigationViewController` with the same map view, and a return to preview when it is dismissed.

```swift
final class PreviewViewController: UIViewController, NavigationMapViewDelegate, NavigationViewControllerDelegate {
    let provider: MapboxNavigationProvider   // the app's provider (see Provider lifecycle)
    var navigationMapView: NavigationMapView!
    var navigationRoutes: NavigationRoutes? {
        didSet {
            guard let navigationRoutes else { return navigationMapView.removeRoutes() }
            // v2 showcase(_:) + showRouteDurations(along:)
            navigationMapView.showcase(navigationRoutes, routeAnnotationKinds: [.routeDurations])
        }
    }

    override func viewDidLoad() {
        super.viewDidLoad()
        navigationMapView = /* standalone NavigationMapView recipe above */
        navigationMapView.delegate = self
        view.insertSubview(navigationMapView, at: 0)   // + constraints
        provider.mapboxNavigation.tripSession().startFreeDrive()   // no puck without it
    }

    // v2: own UILongPressGestureRecognizer + mapboxMap.coordinate(for:). Remove the recognizer.
    func navigationMapView(_ navigationMapView: NavigationMapView, userDidLongTap mapPoint: MapPoint) {
        requestRoute(to: mapPoint.coordinate)
    }

    // v2: didSelect route: Route
    func navigationMapView(_ navigationMapView: NavigationMapView, didSelect alternativeRoute: AlternativeRoute) {
        Task {
            guard let selected = await navigationRoutes?.selecting(alternativeRoute: alternativeRoute) else { return }
            navigationRoutes = selected
        }
    }

    func requestRoute(to destination: CLLocationCoordinate2D) {
        // v2: navigationMapView.mapView.location.latestLocation or passiveLocationManager.location
        guard let origin = provider.mapboxNavigation.navigation().currentLocationMatching?.enhancedLocation else { return }
        var userWaypoint = Waypoint(location: origin, name: "user")
        // On iOS v3 Waypoint(location:heading:name:) takes a CLHeading; set the course on the property instead.
        if origin.course >= 0 { userWaypoint.heading = origin.course }
        let options = NavigationRouteOptions(waypoints: [userWaypoint, Waypoint(coordinate: destination)])
        Task {
            do {
                navigationRoutes = try await provider.mapboxNavigation.routingProvider().calculateRoutes(options: options).value
            } catch { /* keep the app's v2 error handling */ }
        }
    }

    func startNavigation() {
        guard let navigationRoutes else { return }
        // Simulation: provider.apply(coreConfig:) with the location source BEFORE creating the controller.
        let navigationOptions = NavigationOptions(
            mapboxNavigation: provider.mapboxNavigation,
            voiceController: provider.routeVoiceController,
            eventsManager: provider.eventsManager(),
            navigationMapView: navigationMapView   // reuse the preview map; it moves into the controller's view
        )
        let navigationViewController = NavigationViewController(navigationRoutes: navigationRoutes,
                                                                navigationOptions: navigationOptions)
        navigationViewController.delegate = self
        navigationViewController.modalPresentationStyle = .fullScreen
        present(navigationViewController, animated: true)
    }

    func navigationViewControllerDidDismiss(_ navigationViewController: NavigationViewController, byCanceling canceled: Bool) {
        navigationViewController.dismiss(animated: true) { [self] in
            // The controller took the map view, its delegate and its puck, and set the session to idle.
            if let navigationMapView = navigationViewController.navigationMapView { self.navigationMapView = navigationMapView }
            view.insertSubview(navigationMapView, at: 0)   // + constraints
            navigationMapView.delegate = self
            navigationMapView.puckType = .puck2D()
            // If simulation was on for guidance, apply the live location source again here.
            provider.mapboxNavigation.tripSession().startFreeDrive()
            if let navigationRoutes { navigationMapView.showcase(navigationRoutes, routesPresentationStyle: .all(shouldFit: true), animated: true) }
        }
    }
}
```

Differences to tell the developer about, if the v2 screen relied on them: the long press fires on begin, not end; `RoutesPresentationStyle.all` no longer takes `cameraOptions` (bearing and pitch aren't reset); `moveUserLocation(to:)` is gone (the puck follows the trip session); `routeLineTracksTraversal` defaults to `true` on both the map view and the controller.

Custom camera code: `ViewportState.routeProgress` is deprecated and **always returns `nil`** in v3. Read `navigationProgress` instead.

Load the app's map style explicitly on `navigationMapView.mapView`. Without it a v3 `NavigationMapView` shows Maps v11's default (Standard). See Behavior changes.

### 10. Map layer

Use `mapbox-ios-maps-v10-to-v11-migration`. Navigation-specific notes:

- `NavigationMapView.mapView` is a Maps v11 `MapView`. All map APIs on it follow the Maps skill.
- The Maps skill's "pin the v10 default style" check covers `MapView(frame:)`. Apply it to every `NavigationMapView` too: the app gets the same silent change to Standard.
