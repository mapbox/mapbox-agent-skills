# Android: copy the v2 Drop-in UI into the app

Navigation SDK v3 doesn't ship Drop-in UI (`com.mapbox.navigation:ui-dropin`, `NavigationView`). Its sources are public in the [v2 repository](https://github.com/mapbox/mapbox-navigation-android/tree/lts/v2). This option copies them into the app as a module and adapts them to v3. The app keeps its screens, layouts and Drop-in customizations with few changes. Moving the screens to Compose stays a separate, later project.

This file applies only when the inventory found Drop-in usage: the `ui-dropin` dependency, or `com.mapbox.navigation.dropin.NavigationView` in code or layout XML. A "Drop-in screen" below is an activity, fragment or layout that uses that `NavigationView`. Apps without one skip this file.

Present this option as a decision (SKILL.md rule 5). It is the recommended option, but copy nothing until the developer says yes to it with the license terms below in front of them. With no answer, migrate the rest of the app and report Drop-in as an open decision.

## What the developer takes on

- About 130 Kotlin files and 8k lines of UI code that the app now owns, builds and tests
- The copy depends on v3 **`internal`** UI components and helpers (listed below). They are public in Kotlin but not part of the supported API, and can change in any 3.x release. Pin the SDK version, and rebuild and test the module on every SDK upgrade. This approved copy is the one exception to the rule against adding `internal` imports of Mapbox modules: the developer accepts that dependency by saying yes.
- License: the sources are public but not open source. The v2 repository's [`LICENSE.md`](https://github.com/mapbox/mapbox-navigation-android/blob/lts/v2/LICENSE.md) puts them under the Mapbox Terms of Service. State these terms when asking: it requires an active Mapbox account, allows use and modification only with Mapbox products, and doesn't grant unrestricted rights to redistribute or sublicense the code, and modifications that change or interfere with marked portions of the code related to billing, accounting or data collection are not authorized. Don't interpret the license beyond that: if the developer has questions about what it allows, tell them to ask Mapbox support or their Mapbox account contact.

## What to copy

From the `lts/v2` branch:

| Copy                                           | Into                                                        |
| ---------------------------------------------- | ----------------------------------------------------------- |
| `libnavui-dropin/src/main/java`, `/res`        | A new Android library module, for example `:dropin`         |
| `libnavui-app/src/main/java`                   | The same module (it is Drop-in's state store)               |
| `libnavui-dropin/src/main/AndroidManifest.xml` | Keep the `VIBRATE` permission; drop the `package` attribute |

Don't copy `libnavui-base`, `libnavui-util`, `libnavui-maneuver`, `libnavui-tripprogress`, `libnavui-speedlimit`, `libnavui-voice`, `libnavui-maps` or `libnavui-status`: v3 has them in `ui-base`, `ui-utils`, `ui-components`, `ui-maps`, `tripdata` and `voice`.

Keep the v2 package names (`com.mapbox.navigation.dropin`, `com.mapbox.navigation.ui.app.internal`), so the app's Drop-in code needs as few changes as possible. Renaming them is a later cleanup.

Module setup:

- `namespace = "com.mapbox.navigation.dropin"`, `buildFeatures { viewBinding true }`
- `api` dependencies: `com.mapbox.navigationcore:android` and `com.mapbox.navigationcore:ui-components` at the app's v3 version
- AndroidX and Material dependencies the sources import: Material Components, AppCompat, ConstraintLayout, CardView, RecyclerView, Core KTX, Fragment KTX, Activity KTX, Lifecycle (runtime, LiveData, ViewModel), Transition, Kotlin coroutines
- Opt in to `ExperimentalPreviewMapboxNavigationAPI`, `ExperimentalMapboxNavigationAPI` and `MapboxExperimental` in `kotlinOptions.freeCompilerArgs`
- The app module depends on `project(':dropin')` instead of `ui-dropin`. Libraries that came transitively with `ui-dropin` (for example Material Components) must be declared by the app.

## Adapting the copy

Build the module first, then the app. Work through the errors with this table.

| v2 code in the copy                                                                                                                                            | v3 change                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `com.mapbox.navigation.ui.<feature>.internal…` UI components                                                                                                   | Moved to `ui-components`: `ManeuverComponent` → `ui.components.maneuver.internal`; `TripProgressComponent` → `ui.components.tripprogress.internal.ui`; `RoadNameComponent`, `CameraModeButtonComponent`, `RecenterButtonComponent`, `CompassButtonComponent` → `ui.components.maps.internal.ui`; `SpeedInfoComponent` → `ui.components.speedlimit.internal`; `AudioGuidanceButtonComponent` → `ui.components.voice.internal.ui` |
| `RouteLineComponent`, `RouteArrowComponent`, `LocationPuckComponent`, `LocationComponent`, `BuildingHighlightComponent`                                        | Same package, `com.mapbox.navigation.ui.maps.internal.ui`                                                                                                                                                                                                                                                                                                                                                                       |
| v2 views and data APIs (maneuver, trip progress, speed info, road name, voice)                                                                                 | Package renames in `android.md`, Dependencies and setup. Also update view class names in the copied layout XML                                                                                                                                                                                                                                                                                                                  |
| `ViewOptionsCustomization.routeLineOptions: MapboxRouteLineOptions`, `defaultRouteLineOptions(context)`                                                        | Two options: `routeLineApiOptions: MapboxRouteLineApiOptions` and `routeLineViewOptions: MapboxRouteLineViewOptions`, with `defaultRouteLineApiOptions()` (vanishing route line on) and `defaultRouteLineViewOptions(context)` (below `road-label-navigation`). | `override fun getLifecycle(): Lifecycle` (`NavigationView`, `NavigationViewModel`)                                                                             | `override val lifecycle: Lifecycle get() = …` (needed once the resolved AndroidX Lifecycle version is 2.6 or newer, which is usual after the dependency upgrade)                                                                                                                                                                                                                                                                |

| `analytics/AnalyticsComponent` (`sendCustomEvent`)                                                                                                             | Delete it and its `analyticsComponent()` factory. It sent Drop-in usage events to Mapbox through an internal API that v3 removed, so deleting it doesn't interfere with billing, accounting or data collection: nothing remains to send them. | `SpeedLimitViewBinder`, `legacySpeedLimitBinder()`, `speedLimitStyle`, `speedLimitTextAppearance`, `defaultSpeedLimitStyle()`, `mapbox_speed_limit_layout.xml` | Delete them. v3 `internal` APIs the copy keeps using (list them in the report as a risk):

- `com.mapbox.navigation.core.internal.extensions` (`flowRoutesUpdated`, `flowRouteProgress`, `flowLocationMatcherResult`, `attachCreated`, `navigationListOf`, …)
- `com.mapbox.navigation.ui.components.*.internal…` and `com.mapbox.navigation.ui.maps.internal.ui` (the UI components above), `com.mapbox.navigation.ui.maps.internal.extensions`
- `com.mapbox.navigation.ui.utils.internal` (`Provider`, `ViewLifecycleRegistry`, extensions), `com.mapbox.navigation.utils.internal` (logging, `ifNonNull`), `com.mapbox.navigation.base.internal.extensions`

## The app's Drop-in code

Most app code that uses `NavigationView` (`customizeViewOptions`, `customizeViewStyles`, `customizeViewBinders`, `registerMapObserver`, `NavigationViewListener`, `api.startActiveGuidance(...)`) compiles unchanged once the module builds. Then fix:

- `routeLineOptions = …` → `routeLineApiOptions = …` and `routeLineViewOptions = …`, splitting the builder calls as in `android.md`, Route line and arrow
- Speed limit customizations: see the removed rows above. Custom binders that read `locationMatcherResult.speedLimit` move to `speedLimitInfo` (the value is already in the posted unit)
- Map gestures in `MapViewObserver` implementations: move to `LongClickInteraction` / `ClickInteraction`, as in the Maps skill
- `Style.LIGHT`, `Style.DARK` and other style constants passed to `mapStyleUriDay` / `mapStyleUriNight`: they point to newer styles in Maps v11. Pin the v10 URIs (Maps skill)
- Layouts that use `app:accessToken`: keep or remove the attribute; the token resource is enough

## Verify

- The module and the app build, debug and release
- Each Drop-in screen found in the inventory opens without a crash and shows the map
- The navigation states the app uses (free drive, destination preview, route preview, active guidance, arrival) work the way the app reaches them in v2. If the app already simulates trips (`api.routeReplayEnabled(true)`), use that for active guidance; otherwise ask the developer how they test a drive
- Customizations still apply: styles, view binders, options, custom action buttons
- List the removed items (voice player replacement, legacy speed limit view, usage analytics) and the `internal` API dependency in the report
