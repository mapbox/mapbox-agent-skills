# iOS: Navigation SDK v2 → v3

Mappings from Navigation SDK for iOS v2 (`MapboxCoreNavigation`, `MapboxNavigation`) to v3 (`MapboxNavigationCore`, `MapboxNavigationUIKit`).

**Requirements for v3:** Swift 5.9+, **Xcode 16+**, iOS 14+. Navigation v3 depends on Maps SDK v11. Migrate the map layer with `mapbox-maps-v10-to-v11-migration`.

**Distribution: Swift Package Manager only.** v3 has no podspec and no Carthage build. Package URL `https://github.com/mapbox/mapbox-navigation-ios.git`; products `MapboxNavigationCore` and `MapboxNavigationUIKit` (Maps v11 comes in as a dependency). A CocoaPods or Carthage app must move the navigation and map dependencies to SPM. See [Project setup](#project-setup-cocoapods-or-carthage-to-spm). This also applies to Maps v11 in that app, even though Maps v11 itself still ships a podspec: both SDK generations come through the same package graph.

**Libraries:**

| v2                     | v3                                                | Notes                                                                                               |
| ---------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `MapboxCoreNavigation` | `MapboxNavigationCore`                            | Core is rebuilt around one `MapboxNavigation` object and Combine publishers                         |
| `MapboxNavigation`     | `MapboxNavigationUIKit`                           | Same UI components (`NavigationViewController`, `NavigationView`, `PreviewViewController`, CarPlay) |
| `MapboxDirections`     | `MapboxDirections` (bundled)                      | Route requests go through `RoutingProvider`, not `Directions.shared`                                |
| `NavigationMapView`    | `NavigationMapView` in **`MapboxNavigationCore`** | Moved from the UI library to core                                                                   |

**Version notes:** the v3 API changed during 3.x. Check deprecations on the version you target. For example, `RerouteConfig.optionsCustomization` is deprecated in favor of `urlOptionsCustomization`. Release tags changed format at 3.28 (`v3.27.3` → `3.28.0`): compare versions, not tag strings (SKILL.md rule 7).

**Re-exports:** v3 modules don't re-export `UIKit`, `CoreLocation` or `MapboxDirections`. Add `import CoreLocation` (for `CLLocationCoordinate2D`, `CLLocationCoordinate2DMake`) and `import MapboxDirections` (for `RouteOptions`, `Waypoint`, `RouteStep`) where they're used. v2 `import MapboxSpeech` goes away: `SpeechOptions` and `SpeechError` are in `MapboxNavigationCore`.

**Value types:** in v3 `MapboxDirections`, `Waypoint`, `RouteLeg` and `RouteStep` are structs. Code that mutates them through a `let` reference, or relies on reference identity, must change (`var` copies, write back).

**Concurrency:** most v3 map and UI types (`NavigationMapView`, `MapboxSpeechSynthesizer`, UI components) are `@MainActor`. Closures in `CoreConfig` (`multilegAdvancing`, `fasterRouteApproval`) are `@Sendable` and `async`. `Style.apply()` isn't main-actor isolated, so setting `@MainActor` appearance from it needs `MainActor.assumeIsolated` or a `Task { @MainActor in }`.

## New in v3 and on by default

v3 turns on some features that v2 didn't have, or had off by default. Keeping v2 behavior (SKILL.md rule 2) means turning each one off during the migration and listing it in the report as available to turn on later. Present them together as one decision. Checked against v2.23 and v3.35 source.

| Feature                            | v2                                                              | v3 default                                                                       | To keep v2 behavior                                                                                               | Applies when                                                        |
| ---------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Predictive caching                 | Off unless the app passed `predictiveCacheOptions` / enabled it | On: `CoreConfig.predictiveCacheConfig = PredictiveCacheConfig()`                 | `CoreConfig(predictiveCacheConfig: nil)`. If the app already enabled it in v2, keep it and carry its options over | Always check                                                        |
| Vanishing route line               | Off: `routeLineTracksTraversal = false`                         | On: `NavigationMapView.routeLineTracksTraversal = true`                          | `navigationMapView.routeLineTracksTraversal = false` (or the same property on `NavigationViewController`)         | The app shows a route line and didn't turn this on in v2            |
| Restricted areas on the route line | Off: `showsRestrictedAreasOnRoute = false`                      | On                                                                               | `navigationMapView.showsRestrictedAreasOnRoute = false`                                                           | The app shows a route line and didn't turn this on in v2            |
| Route line occlusion by 3D objects | Didn't exist                                                    | `NavigationMapView.routeLineOcclusionFactor = 0.85` (route line fades behind 3D) | `routeLineOcclusionFactor = 0`                                                                                    | The style has 3D buildings or models                                |
| 3D puck                            | 2D puck                                                         | `puckType = .puck3D(.navigationDefault)`                                         | `navigationMapView.puckType = .puck2D()`                                                                          | The app uses `NavigationMapView` without setting the puck           |
| Intersection annotations           | Drawn by `NavigationViewController` only                        | Also drawn by a standalone `NavigationMapView` (`showsIntersectionAnnotations`)  | `showsIntersectionAnnotations = false` on a standalone `NavigationMapView`                                        | The app uses `NavigationMapView` without `NavigationViewController` |

Same default in v2 and v3, no action needed: hybrid routing (`.hybrid`, online preferred), proactive faster-route detection (on, 120 s), route refresh (120 s), continuous alternatives (on), reroute detection (on), automatic leg advancing, and copilot, sensor data, live incidents, electronic horizon and history recording (all off). Not checked: the default speech engine (`ttsConfig = .default` vs the v2 synthesizer) and the speed limit view.

```swift
// v3: replacing reroute and arrival delegate logging
let navigation = mapboxNavigationProvider.mapboxNavigation.navigation()

navigation.rerouting
    .sink { [weak self] status in
        switch status.event {
        case is ReroutingStatus.Events.FetchingRoute:
            self?.analytics.log("nav_reroute_started")
        case let failed as ReroutingStatus.Events.Failed:
            self?.analytics.log("nav_reroute_failed", ["error": failed.error.localizedDescription])
        case is ReroutingStatus.Events.Fetched:
            self?.analytics.log("nav_reroute") // reason not available in v3
        default:
            break
        }
    }
    .store(in: &cancellables)

navigation.waypointsArrival
    .sink { [weak self] status in
        if let arrival = status.event as? WaypointArrivalStatus.Events.ToWaypoint {
            self?.analytics.log("nav_arrived_waypoint", ["leg": arrival.legIndex])
        }
    }
    .store(in: &cancellables)
```

Custom banners and other `NavigationComponent`s inside `NavigationViewController` can keep logging from `onRouteProgressUpdated(_:)`, `onDidPassVisualInstructionPoint(_:)`, `onWillReroute()` and `onDidReroute()` instead of subscribing to the core publishers. `NavigationViewControllerDelegate` also still has progress, reroute and arrival callbacks; check its declaration before moving a UI-only hook to the core publishers.

## Provider lifecycle

v3 allows only **one live `MapboxNavigationProvider`** at a time: creating a second while the first is alive hits `preconditionFailure("MapboxNavigationProvider was instantiated twice.")`. v2 apps often created a `MapboxNavigationService` per screen.

- **One provider per screen** works if the previous screen's provider is released first (Mapbox's own v3 examples own the provider in each view controller). Make sure nothing else retains it.
- **One app-wide provider** works for apps with many navigation screens. Then note which `CoreConfig` fields can change at runtime: `provider.apply(coreConfig:)` re-applies only the location source, TTS config, locale, log level, credentials token and copilot. Other fields (`multilegAdvancing`, `routingConfig` including reroute and faster-route config, `historyRecordingConfig`, `electronicHorizonConfig`, `predictiveCacheConfig`) only take effect when the navigator is created. Per-screen differences in those need a decision.
- `CoreConfig ==` and `TTSConfig ==` compare closures and custom synthesizers by presence, not identity. Don't rely on equality to detect a changed closure.

`NavigationViewController` lifecycle in v3: it calls `tripSession().startActiveGuidance(with:startLegIndex: 0)` itself when its view loads, doesn't configure simulation (set `locationSource` on the provider **before** creating it), and sets the session to idle when dismissed.

| v2 feature                                                                      | What to do                                                                                                                                     |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Custom routing provider (`customRoutingProvider`)                               | **Blocker.** Escalate to Mapbox. If it only sets request parameters, use `NavigationRouteOptions` and `RerouteConfig.urlOptionsCustomization`. |

| Rich arrival feedback (`EndOfRouteFeedback`)                                    | Decision: log the Boolean only                                                                                                                 |
| Raw `RouteResponse` for logging                                                 | Decision: log what the app needs at request time                                                                                               |
